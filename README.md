# TaskFlow API

Учебный REST API для управления личными задачами. Позволяет создавать задачи, просматривать их, отмечать выполненными, удалять и получать статистику.

В проекте используются две основные ветки:

main — стабильная версия приложения, предназначенная для использования и проверки.

develop — ветка разработки, в которой выполняются изменения, добавляются новые функции и тесты.

Для запуска стабильной версии приложения необходимо использовать ветку main.

Проект подготовлен в рамках дисциплины «Инфраструктура и администрирование». Стек: **Python 3.11+**, **FastAPI**, **pytest**, **GitHub Actions**.



## 1. Возможности

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/` | Ссылка на документацию |
| GET | `/health` | Проверка, что приложение работает |
| GET | `/version` | Версия приложения |
| GET | `/tasks` | Список задач; можно фильтровать по `?completed=true` |
| POST | `/tasks` | Создать задачу |
| GET | `/tasks/stats` | Число всех, выполненных и открытых задач |
| GET | `/tasks/{task_id}` | Получить задачу по ID |
| PATCH | `/tasks/{task_id}` | Изменить название, описание или статус |
| DELETE | `/tasks/{task_id}` | Удалить задачу |

## 2. Установка и запуск

Откройте терминал в папке проекта. Нужен установленный Python **3.11 или новее**.

### macOS / Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
cp .env.example .env
python -m uvicorn app_final:app --reload --host 127.0.0.1 --port 8000
```

### Windows (PowerShell)

```powershell
py -3 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
Copy-Item .env.example .env
python -m uvicorn app_final:app --reload --host 127.0.0.1 --port 8000
```

Откройте в браузере:

- http://127.0.0.1:8000/docs — интерфейс Swagger UI для тестирования API;
- http://127.0.0.1:8000/health — проверка работоспособности;
- http://127.0.0.1:8000/version — версия приложения.

Для **обычной работы без автоматического перезапуска** запустите:

```bash
python -m uvicorn app_final:app --host 127.0.0.1 --port 8000
```

Для остановки сервиса нажмите `Ctrl+C`.

## 3. Проверка маршрутов

Эти команды выполняются во **втором** терминале, пока сервер запущен.

Проверка `/health`:

```bash
curl http://127.0.0.1:8000/health
```

Ожидаемый ответ: `{"status":"ok"}`.

Проверка `/version`:

```bash
curl http://127.0.0.1:8000/version
```

Создание задачи:

```bash
curl -X POST http://127.0.0.1:8000/tasks \
  -H 'Content-Type: application/json' \
  -d '{"title":"Сдать проект","description":"Проверить GitHub Actions"}'
```

Новая задача обычно получит `id: 1` (если это первая задача после запуска).

Просмотр списка и одной задачи:

```bash
curl http://127.0.0.1:8000/tasks
curl http://127.0.0.1:8000/tasks/1
```

Отметить задачу выполненной:

```bash
curl -X PATCH http://127.0.0.1:8000/tasks/1 \
  -H 'Content-Type: application/json' \
  -d '{"completed":true}'
```

Статистика и фильтрация:

```bash
curl http://127.0.0.1:8000/tasks/stats
curl 'http://127.0.0.1:8000/tasks?completed=true'
```

Удаление задачи:

```bash
curl -X DELETE -i http://127.0.0.1:8000/tasks/1
```

После удаления ответ имеет код **204**, а повторный GET `/tasks/1` — **404**.

Можно использовать и `/docs`: выберите маршрут → **Try it out** → укажите параметры → **Execute**.

## 4. Переменные окружения

Скопируйте файл `.env.example` в `.env` для локальной настройки. Файл `.env` исключён из Git.

| Переменная | Значение по умолчанию | Смысл |
| --- | --- | --- |
| `APP_NAME` | `TaskFlow API` | Название в API и Swagger |
| `APP_VERSION` | `1.0.0` | Версия в `/version` |
| `LOG_LEVEL` | `INFO` | Уровень логирования (`DEBUG`, `INFO`, `WARNING` и т. д.) |
| `MAX_TASKS` | `100` | Максимальное число хранимых задач |

`MAX_TASKS` должен быть **целым положительным числом**. Когда лимит достигнут, POST `/tasks` возвращает ошибку **409 Conflict**. После изменения переменных окружения перезапустите сервер.



## 5. Автоматические тесты

После установки `requirements-dev.txt` запустите из корня проекта:

```bash
python -m pytest -v
```

Тесты проверяют `/health`, `/version`, создание и получение задачи, некорректные параметры, отсутствующие задачи (404), изменение задачи, фильтрацию, статистику, удаление и ограничение через `MAX_TASKS`. Каждый тест получает пустое хранилище.



## 6. GitHub Actions и artifact

Файл `.github/workflows/ci.yml` содержит workflow, который запускается при каждом `push` и `pull_request`:

1. Забирает репозиторий на виртуальную машину Ubuntu.
2. Устанавливает Python 3.11 и зависимости.
3. Выполняет `python -m pytest -v`.
4. **Только после успешных тестов** загружает файлы приложения как artifact `taskflow-api-<номер запуска>`.


## 7. Логи и диагностика

Логи показываются в терминале, где запущен `uvicorn`. В них отображаются старт и остановка сервиса, HTTP-методы, адреса запросов, коды ответов, создание/обновление/удаление задач и предупреждение о лимите.

| Проблема | Что проверить |
| --- | --- |
| `ModuleNotFoundError` | Активировано ли `.venv` и выполнена ли установка зависимостей |
| `Error loading ASGI app` | Запускать `app_final:app` **без `.py`** и из каталога проекта |
| `Address already in use` | Порт занят. Запустить на `--port 8001` и использовать этот порт в URL |
| GET `/tasks/1` выдаёт 404 | Сначала создать задачу через POST `/tasks`; после перезапуска список пуст |
| POST `/tasks` выдаёт 422 | Проверить JSON и непустое название `title` |
| POST `/tasks` выдаёт 409 | Достигнут `MAX_TASKS`; удалить задачу или увеличить лимит и перезапустить |
| Ошибка старта про `MAX_TASKS` | Установить в `.env` положительное целое число, например `100` |
| Тесты не запускаются | Выполнить `python -m pip install -r requirements-dev.txt` и повторить |
| CI красный | Открыть **Actions** → неуспешный запуск → лог шага `Run automated tests` |
| Artifact не появился | Проверить, завершились ли тесты успешно и выполнился ли шаг `Upload application artifact` |

Для проверки статуса без браузера используйте `curl http://127.0.0.1:8000/health`; для версии — `/version`.
